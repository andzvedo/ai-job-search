My services: Register a new service

Solution

The business team defined with the engineering team that the MaaS platform needed two main applications:

  • MaaS Console

    Marketplace for physical services where retail stores could hire, and manage the usage and pay on-demand, similar to what Firebase did it for cloud services.

  • Maas Account.

    An account manager for managing multiple organization profiles, and users' profiles, their roles, and permissions to access in the MaaS Console.

The Maas Console has two views, one is Public and the other is Registered.

At the Public view, the main challenge was to show the services available to hire and authenticate users integrating with the MaaS Account application because without authentication it wasn't possible to hire any service, just browse the relevant information, like details about the service, images, technical documentation of how to integrate, and plans offered.

At the Registered view, and with an organization associated, the main challenge was to transform a very complex and extensive service registration process into a clear and descriptive experience for the users and organizations that wanted to sell their own services in the MaaS Console and hire services from others as well.

Based on that, the company visualized the need to create a platform, called MaaS (Magalu as a Service), which was formed by two main applications: MaaS Console and Maas Account.

MaaS Console was a marketplace for services, where was possible to hire, sell, and manage services, and MaaS Account was for managing multiple accounts for one company, or multiple companies, user profiles, and their permissions within MaaS.

The Maas Console has two views, one is Public and the other is Registered. Fro the public view some of the challenges were:

  • Show the services available to hire in the marketplace, and authenticate users in a seamless flow, integrating with the MaaS Account application.
    • Without authentication it wasn't possible to hire any service, just browse the relevant information, like details about the service, images, technical documentation of how to integrate, and plans offered in the marketplace.
Description

In this project, I faced some intriguing challenges, working with a lot of technical specifications, such as:

  • How to register a set of endpoints that compose an API, that later could be hired and integrated into another service,
  • Manage versions
  • How to manage roles, and permissions, multiple organizations of the users?
  • How to create an interface that is simple to use, even when the subject is complex?

User Interface

Details

To design the user interface we followed the Material Design Guidelines, doing some small customizations to the visual of the components to adapt to the platform's needs and the Magazine Luiza visual identity, as one of the Front-End development requirements to speed up the process was to use the Material UI react framework.

Layout, Grid, and Spacing

Was used the 4 pt baseline grid to position the typography, and for most of the elements on the pages was used multiples of 4, like 12, 16, 20, 24, 32, 64px, and so on.

The grid had 12 columns with a 24px gutter for displaying the content. The platform is responsive but the main focus was desktop.
